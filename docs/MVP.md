# MVP: 하루 1세션 진단 UX

personal-english **첫 버전(MVP)** 에서 사용자가 매일 한 번 거치는 시나리오와, 그에 맞는 화면·데이터·완료 기준을 정의한다.

기술 스택·저장 방식은 [TECH_DECISIONS.md](./TECH_DECISIONS.md)를 따른다 (로컬 IndexedDB/Dexie, 서버 DB 없음).

## 1. MVP가 검증하려는 것

README의 한 줄 목표:

> 문장이 이어질 때 **어디서** 이해가 끊기는지 기록하고, 그 이유가 **단어 / 문장 구조 / 소리** 중 무엇인지 구분한다.

MVP에서는 **퀴즈 정답률**이 아니라 **자기 진단 + 기록**이 핵심이다.

## 2. 하루 1세션 시나리오 (사용자 관점)

**전제:** 세션 길이 약 5~10분, passage **1개**만 다룬다.

| 단계                     | 사용자 행동                                            | 앱 반응                                             |
| ------------------------ | ------------------------------------------------------ | --------------------------------------------------- |
| **S0. 시작**             | 홈에서 “오늘 세션 시작”                                | 오늘 passage 1개 로드 (시드 콘텐츠)                 |
| **S1. 모드 선택**        | “듣기부터” 또는 “읽기부터” 선택                        | 같은 passage, 모드 UI 전환                          |
| **S2. 따라가기**         | 오디오 재생 / 전사(transcript) 읽기                    | 재생 위치·문장 하이라이트(선택), 속도 0.75~1x(선택) |
| **S3. 끊김 표시**        | “여기부터 모르겠다” — **문장** 또는 **구간** 선택      | 선택 구간 저장 후보로 표시                          |
| **S4. 원인 태그**        | 끊긴 지점마다 **단어 / 구조 / 소리** 중 1개(이상) 선택 | `CauseTag` 기록                                     |
| **S5. (선택) 미니 연습** | 태그별 2~3개 짧은 힌트·확인 (MVP는 최소)               | v0에서는 “다음에” 가능 — 문서상 optional            |
| **S6. 세션 요약**        | 오늘 끊김·태그 개수 확인                               | 로컬 저장, 홈에 간단 통계                           |

**성공:** S3~S4를 최소 1회 이상 하고 S6까지 도달하면 “오늘 세션 완료”.

## 3. 화면 (MVP v0)

| 화면            | 경로(가칭)           | 필수 요소                                       |
| --------------- | -------------------- | ----------------------------------------------- |
| **홈**          | `/`                  | 오늘 세션 시작, (선택) 최근 7일 태그 비율 한 줄 |
| **세션 — 듣기** | `/session`           | `<audio>`, 전사, 재생/일시정지, (선택) 속도     |
| **세션 — 읽기** | `/session?mode=read` | 전사만, 듣기와 동일 passage                     |
| **진단 패널**   | 세션 내 고정/시트    | 끊김 문장 선택, 원인 3버튼                      |
| **요약**        | `/session/summary`   | 오늘 `Breakpoint` 목록, 태그 counts             |

와이어 수준 상세는 구현 이슈에서 shadcn 컴포넌트로 맞춘다.

## 4. 도메인 데이터 (Dexie 설계 입력)

MVP v0에서 **로컬에 저장**할 최소 모델 ([TECH_DECISIONS.md](./TECH_DECISIONS.md) §3 함께 쓰는 도구).

### 4.1 열거형

```ts
type CauseTag = "word" | "structure" | "sound";
type SessionMode = "listen" | "read";
```

### 4.2 엔티티 (개념)

| 엔티티          | 필드 (개념)                                                    | 설명                           |
| --------------- | -------------------------------------------------------------- | ------------------------------ |
| **Passage**     | id, title, transcript, audioUrl?, difficulty?                  | 시드 JSON; MVP 1~3개           |
| **Session**     | id, passageId, startedAt, completedAt?, mode                   | 하루 1세션 = 1 Session         |
| **Breakpoint**  | id, sessionId, sentenceIndex, optional char range, causeTags[] | “여기서 끊김” + 원인           |
| **UnknownWord** | (선택 v0) word, passageId, sessionId                           | 단어 태그 시 자동 제안은 2단계 |

### 4.3 저장 규칙

- 세션 중: React state + 종료 시 Dexie persist.
- 브라우저 데이터 삭제 시 기록 소실 (MVP acceptable).

## 5. MVP 포함 / 제외

### 포함

- passage 1개 기준 end-to-end: 듣기 **또는** 읽기 → 끊김 → 태그 → 요약 → 로컬 저장
- 전사 표시, 문장 단위 끊김 표시
- 원인 3종 태그
- 시드 passage **최소 1개** (목표 3개는 별도 이슈 가능)

### 제외 (명시적 미룸)

- 계정·동기화·서버 DB
- STT, TTS, wavesurfer 파형
- 미니 드릴 자동 생성, unknown word 사전 연동
- 스트릭/푸시 알림
- 다 passage 일일 로테이션 알고리즘

## 6. 완료 기준 (프로젝트 MVP)
